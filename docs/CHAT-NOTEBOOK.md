# 채팅별 메모·문서

OpenMuse 0.8.0부터 기본 채팅과 각 별도 채팅 상단의 **메모·문서**에서 다음 내용을 관리합니다.

- **카테고리**: 홈서버, 프로젝트 이름, 업무 등으로 분류합니다.
- **이슈·주제**: 현재 작업이나 이슈 번호를 적습니다. 대화 목록에서 카테고리·이슈·대화 이름으로 검색합니다.
- **주요 메모**: IP, URL, 접속 명령, 프로젝트 경로, 작업 목표처럼 항상 참고할 정보를 적습니다.
- **참고 문서**: 제목과 Markdown/일반 텍스트 본문을 작성하고 수정·미리보기·삭제합니다.
  **이 문서 고정**을 켜면 항상 참고합니다. 긴 문서는 고정을 해제하면 AI가 문서 목록을 보고 필요한 부분을 읽습니다.

**메모·문서 저장**을 눌러 적용합니다. 재접속/서버 재시작 후에도 DB에 유지됩니다.
답변 중에 저장한 내용은 다음 답변부터 적용합니다. 여러 창에서 동시에 수정하면 저장 버전 충돌을 표시하고
기존 입력을 유지하므로, 필요한 내용을 복사한 뒤 최신 내용을 불러와 병합할 수 있습니다.
보관한 대화는 메모 열람이 가능하고 편집하려면 먼저 복원합니다.

주요 메모는 6,000자, 참고 문서는 20개/각 40,000자, 전체 메모·문서 본문은 160,000자까지입니다.
항상 전달하는 주요 메모와 고정 문서 합계는 12,000자로 제한하며, 초과 내용을 조용히 생략하지 않고 저장 오류를 표시합니다.
이 화면은 문서 작성용입니다. 파일·폴더 업로드와 PDF 읽기는 채팅 입력창의 기존 첨부 기능을 사용합니다.

## AI가 사용하는 방식

매 응답 시작 시 서버가 현재 채팅의 저장 내용을 다시 읽어 모델 지침의 참고 자료 영역에 넣습니다.
클라이언트가 대화 기록에 붙여 넣는 방식이 아니므로 대화 요약·새로고침·모델 변경 후에도 최신 내용이 전달됩니다.
주요 메모/고정 문서의 본문과 나머지 문서의 목록을 전달하며, `list_thread_documents`와
`read_thread_document`로 해당 채팅의 문서만 읽습니다. Pi와 일반 모델 경로 모두 동일하게 적용됩니다.
오래된 메모를 현재 정보로 취급하지 않도록 저장 버전과 최신 내용 우선 지침도 전달합니다.
이 기능은 정보를 매번 제공하는 것이며 모델의 판단 정확성까지 보장하는 것은 아닙니다.

“기억해 줘”로 명시적으로 저장을 요청하면 기본적으로 이 채팅의 고정 문서로 보관합니다.
사용자가 모든 채팅에서 공유하도록 명시한 경우에만 워크스페이스 기억으로 저장합니다.
기존 워크스페이스 기억은 그대로 유지됩니다. 새 채팅별 메모를 자동으로 전체 기억에 복사하지 않습니다.

해당 채팅에서 맡긴 작업에는 생성 당시 메모·문서의 사본을 저장합니다. 팀의 각 역할과 재시도도 같은 사본을 사용하므로
작업 도중 수정한 접속 정보 때문에 실행 조건이 바뀌지 않습니다. 수정된 내용을 적용하려면 새 작업을 요청하세요.
대화 완전 삭제 시 그 대화의 메모는 함께 삭제되며, 이미 생성된 작업의 사본은 작업 기록에 남습니다.
메모/문서는 작업 참고 자료이며 커넥터 권한이나 승인 설정을 바꾸지 않습니다.

## API

- `GET /api/copilotkit/threads/:id/knowledge`: 소유자의 해당 대화 메모 조회.
- `PUT /api/copilotkit/threads/:id/knowledge`: `revision`, `category`, `issue`, `notes`, `documents` 저장.
  문서는 `{id,title,content,pinned}` 형식입니다. 서버가 revision을 증가시키며 오래된 revision은 HTTP 409로 거부합니다.
- `GET /api/copilotkit/threads?query=...`: 이름·카테고리·이슈 검색. 목록에는 분류와 문서 개수만 표시하고 본문은 포함하지 않습니다.

외부 서비스나 클라우드 프로젝트 키를 추가로 요구하지 않습니다.
