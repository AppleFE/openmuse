# 채팅 이미지·파일·폴더 첨부

OpenMuse 0.7.0의 채팅 입력창 **+ → 이미지 / 파일 / 폴더**로 첨부합니다.
여러 파일을 선택할 수 있고, 폴더의 하위 상대 경로를 유지합니다. 웹에서는 파일·폴더를
채팅 영역에 끌어 놓거나 **Ctrl+V / Cmd+V**로 클립보드 이미지·스크린샷을 붙여넣을 수 있습니다.
일반 텍스트 붙여넣기는 기존 입력 동작을 유지합니다. 파일 붙여넣기는 브라우저가 클립보드에
파일 데이터를 제공하는 경우에 지원합니다. OS/브라우저 조합에서 제공하지 않으면 파일 선택이나
드래그 앤 드롭을 사용하세요. 네이티브 앱은 파일 선택과 **클립보드 이미지** 버튼을 제공하며
폴더 선택은 웹에서 지원합니다.

- 이미지 미리보기, 전송 전 개별 제거, 보낸 파일의 원본 다운로드, 대화 재접속 후 첨부 표시를 지원합니다.
- 파일 하나 20 MiB, 한 메시지 합계 100 MiB/200개까지. 이미지는 한 메시지 6개/합계 20 MiB까지입니다.
  PNG/JPEG/WebP/GIF를 지원하며 4,000만 화소/한 변 16,000픽셀로 제한합니다.
- 폴더 선택과 드롭에서 `.git`, `node_modules`, `__pycache__`, `.venv`는 제외합니다.
  그 밖의 파일은 선택한 그대로 업로드됩니다. 빈 폴더는 첨부되지 않습니다.
- 텍스트·코드·CSV·JSON·PDF는 `list_attachments` / `read_attachment`로 실제 내용을 읽습니다.
  PDF는 페이지/문자 위치별 텍스트 추출이며 스캔본·도표 OCR은 지원하지 않습니다.
  압축파일·Office 문서 등 나머지 형식은 저장/다운로드로 표시하며 자동 추출하거나 실행하지 않습니다.
- 이미지는 이미지 입력을 지원하는 모델에 실제 바이트로 전달합니다. OpenCodex가 이미지 지원을
  알린 기존 모델에도 `vision` 기능이 반영됩니다. 미지원 모델은 오류와 모델 변경 안내를 표시합니다.
  Pi 세션에는 이미지가 대화 컨텍스트로 전달되며, 일반 런타임은 현재 메시지의 이미지를 전달합니다.
  오래된 이미지를 다시 분석하려면 재첨부하세요.
- 서버의 `dataDir/attachments`에 원본, DB에 소유자/대화별 메타데이터를 저장합니다.
  대화 기록은 파일 ID를 보관하고, 모델 호출 때 이미지 데이터로 변환하므로 재시도 시 원본 기록을
  수정하지 않습니다. 다운로드 링크는 서명되고 15분 후 만료되며, 열린 채팅에서 갱신됩니다.
  대화를 완전히 삭제하면 연결된 첨부 파일도 삭제됩니다.

API: 인증된 `POST /api/attachments`에 multipart `threadId`, 반복 `files`, 선택적인 JSON 배열 `paths`를
전송합니다. `GET /api/attachments?threadId=...`로 목록, `DELETE /api/attachments/:id`로 아직 전송하지
않은 파일을 제거합니다. 응답의 서명된 `url`은 열람/다운로드용이며 다른 대화의 파일 ID를 재사용할 수 없습니다.
